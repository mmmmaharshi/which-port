# Zig 0.17: what moved, and how to find it

Reach this when an API you remember is missing, or before hand-declaring a
foreign function. Most of this session's compile errors were recalling a 0.11-era
API that 0.17 deleted. The answer is always in the stdlib source on disk.

**Grep before you recall.** One command answers most of these:

```powershell
Select-String -Path "<zig-root>\lib\std\**\*.zig" -Pattern "pub fn <name>"
```

Find the root with `Split-Path -Parent (Get-Command zig).Source` then follow the
`zig.exe` symlink — winget puts the real tree under
`AppData\Local\Microsoft\WinGet\Packages\...`.

## Removed, with the replacement

| Gone in 0.17 | Use instead |
| --- | --- |
| `std.fs.File` | `std.Io.File` — `std.Io.File.stdout()`, `.stderr()`, `.writeStreamingAll(file, io, bytes)` |
| `std.fs.Dir` iteration | `std.Io.Dir` — `iterate(dir)` then `next(it, io)` |
| `std.heap.GeneralPurposeAllocator` | `std.heap.page_allocator` (right for a one-shot CLI anyway) |
| `std.net` | `std.Io.net` |
| `std.posix.socket` / `bind` / `listen` | `std.Io.net`, or a libc `extern` for tests |
| `std.process.args`, `std.process.argsAlloc` | `pub fn main(init: std.process.Init.Minimal) u8` then `init.args.toSlice(arena)` |
| `std.os.windows.GetCommandLineW` | supplied by that same `main` signature |
| `std.sort.heap`'s local comparator | fine, but share it from the seam, not per platform |

`main(init: std.process.Init.Minimal)` is the big one: it hands `main` the argv
vector on **every** platform, so you never hand-roll `GetCommandLineW` and never
need a POSIX `#ifdef` for argv.

## Every call takes an explicit `Io`

0.17 moved I/O behind an interface value. Create one and thread it:

```zig
var threaded: std.Io.Threaded = .init(gpa, .{}); // TWO arguments
defer threaded.deinit();
const io = threaded.io();
```

`std.Io.Threaded.init` takes `(gpa, options)` — one argument is a compile error.
`.init(gpa, .{})`.

## Traps that cost the most time

- **procfs reports `st_size` 0.** `Io.Dir.readFileAlloc` therefore returns an
  **empty slice with no error**, and a live socket reads as "port is free".
  Loop on the raw syscall instead: `std.posix.read(file.handle, buf[used..])`
  until it returns 0.
- **A `Dir` cannot be iterated unless opened with `.{ .iterate = true }`.**
  Without it `iterate()` yields nothing and no error says so.
- **Error set names are not where you expect.** `Io.Dir` exports `OpenError`,
  `AccessError`, `ReadLinkError`, `ReadFileAllocError` — there is no
  `OpenDirError` or `OpenFileError`. And `File` is `std.Io.File`, *not* under
  `Io.Dir`. Grep `pub const \w*Error` in `Dir.zig` rather than guessing.
- **`std.ArrayList` is unmanaged**, so `append` needs an allocator:
  `out.append(gpa, item)`.
- **`catch break` is illegal as a `while` condition operand.** Use
  `catch null` and end the loop.
- **`@ptrCast` needs a known result type.** Allocate the array you want
  (`[]u32`) and pass `.ptr`, rather than casting a byte buffer.
- **`_ = x` on a used local is "pointless discard".**

## Win32, since we hand-declare it

Zig ships **no** `GetExtendedTcpTable` or `MIB_TCPROW`. Declare them yourself;
no Windows SDK needed. Read the real layouts from the headers already on disk
rather than recalling them — `C:\msys64\ucrt64\include\iprtrmib.h` has the
`TCP_TABLE_CLASS` enum and both row structs; `iphlpapi.h` has the declaration.

Three things that cost real time to get wrong:

1. `GetExtendedTcpTable` is in **`iphlpapi.dll`**, not `kernel32`. The link
   fails loudly, which is the good case.
2. Parameter 4 is **`ulAf` (address family)**, parameter 5 is the table class.
   `AF_UNSPEC` (0) returns `ERROR_INVALID_PARAMETER`, so the table must be read
   **twice** — once for `AF_INET`, once for `AF_INET6`. That double call is
   exactly what produces a dual-stack pair as two rows.
3. `TCP_TABLE_OWNER_PID_LISTENER` is `3`. The returned size is a **capacity**,
   not an exact length: count rows from the leading `dwNumEntries`, never from
   the byte count.

The call needs **no elevation**. The live round-trip test in `win_test.zig`
asserts that, so it is a regression test for it.
